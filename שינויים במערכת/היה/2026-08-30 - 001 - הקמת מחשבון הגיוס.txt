מה התבקש
---------
המרת הפרויקט המשוכפל (סימולטור שכר) למחשבון גיוס, על בסיס שני קובצי
אקסל - פעילויות וגיוסים - ועל בסיס המחשבון הקודם AAA13.HTML.
לצד הבקשה צורף אפיון שנכתב בגמיני, אך המשתמש ביקש במפורש שהמערכת
תיבנה על האקסלים בלבד. כמו כן: שינוי שם התיקייה ל«מחשבון גיוס»,
קובץ עצמאי שנפתח בלחיצה כפולה, וגרסת GitHub.

מה בוצע
--------
1. התיקייה שונתה מ«מערכת גיוס» ל«מחשבון גיוס». היא הייתה נעולה על ידי
   תהליך אחר ולכן בוצעה העתקה, אימות זהות מלאה, ומחיקת המקור.

2. נוקו כל שרידי סימולטור השכר. כל הקבצים המקוריים נותרו שלמים
   בתיקייה /mnt/c/projects/salary_calculator, ולכן לא אבד דבר.

3. כל המספרים חושבו מחדש מהאקסלים. המספרים שבאפיון של גמיני לא שימשו,
   ובבדיקה התברר שחלקם מוטים - ראו סעיף "מה לא בוצע".

4. נבנתה המערכת: config/params.json, tools/build_dataset.py,
   tools/build_web.py, tools/verify_sources.py, recruit_calc/engine.py,
   recruit_calc/cli.py, web/template.html, ו-35 בדיקות.

5. שני קובצי פלט זהים: index.html לגרסת GitHub Pages, ו«מחשבון גיוס.html»
   כקובץ עצמאי לפתיחה בלחיצה כפולה. שניהם ללא ספריות חיצוניות וללא
   קריאות רשת.

6. make ו-make test עוברים במלואם.

מה לא בוצע ולמה
----------------
1. מספרי האפיון של גמיני לא אומצו. הם חושבו כשגם הפעילויות וגם הגיוסים
   נחתכו ב-20.05.2026, וזה מכניס בדיוק את ההטיה שהאפיון התיימר למנוע:
   נספרו רק מועמדים שהתגייסו מהר. כך יצא באפיון שחציון הזמן מבדיקת
   קבצים ועד גיוס הוא 4 ימים. החישוב מהנתונים נותן 71 ימים.
   במקום מספר יחיד, המערכת מציגה טווח בין שני בסיסי חישוב.

2. לא נבנה מודול בדיקת מועמדים (Candidate Inspector) שהופיע באפיון.
   הוא היה מחייב הטמעת מזהי מועמדים בתוך עמוד שמתפרסם באופן ציבורי
   ב-GitHub Pages. קובצי המקור הוחרגו מהמאגר מאותה סיבה.

3. לא נבנתה העלאת אקסלים מהדפדפן (SheetJS). המשתמש בחר בנתונים

def categorize_time(days):
    if days <= 7:
        return "עד שבוע"
    elif days <= 14:
        return "שבוע עד שבועיים"
    elif days <= 30:
        return "שבועיים עד חודש"
    elif days <= 60:

    elif days <= 90:
        return "חודשיים עד 3 חודשים"

## 3. כללי עיבוד נתונים וחיתוך סטטיסטי (Cutoff Rules)

### 3.1 חיתוך נתונים עד ה-20.05.2026 (Right-Censoring Prevention)

משך תהליך גיוס ממוצע מקצה לקצה עומד על **כ-3 חודשים**.
נתונים שנרשמו לאחר תאריך ה-20.05.2026 מייצגים מועמדים שנמצאים בעיצומו של המשפך וטרם הספיקו להשלים את הגיוס עד סוף אוגוסט. הכללת מועמדים אלו בחישוב יחסי ההמרה תעוות את היחסים (תציג תמונה כאילו אחוז מעבר נמוך בהרבה ממה שהוא באמת).

עבור כל שלב במשפך, הספירה מבוצעת ברמת **מועמד ייחודי** ולא ברמת שורת פעילות. מועמד שהופיע מספר פעמים באותו שלב ייספר **פעם אחת בלבד** בשלב זה.
