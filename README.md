# מחשבון גיוס

מחשבון שמתרגם מספר מועמדים בשלב כלשהו במשפך הגיוס לתחזית של מספר המגויסים
הצפוי, של מספר המועמדים הדרוש בכל שלב אחר, ושל מועדי הקליטה הצפויים.

**[פתיחת המחשבון](https://recruitment-demos.github.io/recruitment-calculator/)**

כל מספר במערכת נגזר משני קובצי מקור - פעילויות וגיוסים בפועל. אין מספרי
בסיס שנכתבו ידנית בקוד.

## שני קבצים, אותו תוכן

| קובץ | שימוש |
| --- | --- |
| `index.html` | הגרסה שמוגשת ב-GitHub Pages |
| `מחשבון גיוס.html` | קובץ עצמאי לשליחה או לפתיחה בלחיצה כפולה |

שניהם עצמאיים לחלוטין: הנתונים מוטמעים בתוך ה-HTML, אין קריאות רשת ואין
ספריות חיצוניות. שניהם תוצרי בנייה - **אין לערוך אותם ידנית.**

## למה כל תוצאה היא טווח

הנתונים קטועים מימין: מועמד שביצע פעילות סמוך לסוף התקופה עדיין לא הספיק
להתגייס, ובקובץ הוא נראה כמי שלא התגייס. הראיה נמצאת ב-`make verify` - יחס
הגיוס בבדיקת קבצים יורד מ-13% בקוהורט מרץ ל-1% בקוהורט יולי, לא מפני
שהאיכות ירדה אלא מפני שלא עבר מספיק זמן.

לכן כל יחס נמדד פעמיים:

- **גבול תחתון** - כל המועמדים עד תאריך חיתוך קבוע, מול הגיוסים שלהם לאורך
  כל הקובץ. חלק מהם עדיין בתהליך, ולכן היחס נוטה כלפי מטה.
- **גבול עליון** - רק קוהורטים שהספיקו להבשיל. תאריך החיתוך נקבע לכל שלב
  בנפרד: תאריך הגיוס האחרון בקובץ, פחות האחוזון ה-90 של זמן הגיוס באותו שלב.

התוצאה האמיתית נמצאת בין השניים.

## הנתונים

| שלב | יחס גיוס | חציון ימים לגיוס |
| --- | --- | --- |
| הגשות | אין מקור נתונים | — |
| בדיקת קבצים | 8.9% – 10.9% | 71 |
| זימון למבחן מקוון | 17.1% – 19.1% | 86 |
| יום מיון מקוון | 23.1% – 24.4% | 66 |
| יום מיון | 40.9% – 43.6% | 56 |
| מרכז הערכה | 50.1% – 50.3% | 31 |
| יחב"מ | 77.5% – 78.0% | 17 |

מרכז הערכה הוא שלב סלקטיבי שרק חלק מהמועמדים עוברים בו, ולכן מספר המועמדים
בו קטן ממספר הגיוסים באותה תקופה. המשפך אינו סדרתי, והמעבר בין שלבים נעשה
תמיד דרך הגיוסים ולא כשרשרת אחוזי מעבר.

## פקודות

```bash
make          # בניית הנתונים + שני עמודי המחשבון
make test     # 35 בדיקות
make verify   # דוח בדיקה של קובצי המקור
make basis    # יחסי הגיוס וזמני הגיוס בשורת פקודה
```

שורת פקודה:

```bash
python3 -m recruit_calc.cli --from online_day 100 --timeline --target 30
```

## עדכון נתונים

מחליפים את קובץ האקסל בתיקיית «נתונים למערכת» ומריצים `make`. אין לערוך
ידנית את `data/recruitment_data.json` או את קובצי ה-HTML.

אם יתקבל קובץ הגשות - מוסיפים אותו ל-`config/params.json` ומריצים `make`.
עד אז שלב «הגשות» מסומן כשלב ללא נתונים ואינו משתתף בחישוב.

## שני מנועי חישוב

יש לוגיקת חישוב גם ב-`recruit_calc/engine.py` וגם ב-JS שבתוך
`web/template.html`. כל שינוי בלוגיקה חייב להיעשות בשניהם.
`tests/test_parity.py` מריץ את שניהם על מאות תרחישים ומוודא שהם מחזירים
בדיוק אותו דבר.

## פרטיות

קובצי המקור מכילים מספרי מועמד. הם נשארים בתיקיית «נתונים למערכת» ואינם
נכנסים לעמוד הבנוי, שמתפרסם באופן ציבורי. המחשבון מכיל נתונים מצרפיים בלבד.

תיעוד מלא: `אפיון המערכת.txt`
