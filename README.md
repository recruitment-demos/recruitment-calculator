# מחשבון גיוס

מזינים כמה מועמדים נמצאים עכשיו בשלב מסוים במשפך הגיוס, ומקבלים כמה מהם
יגיעו לכל שלב בהמשך, מתי, וכמה מהם יגויסו.

**[פתיחת המחשבון](https://recruitment-demos.github.io/recruitment-calculator/)**

כל מספר נגזר משני קובצי מקור - פעילויות וגיוסים בפועל. אין מספרי בסיס
שנכתבו ידנית בקוד.

## שני קבצים, אותו תוכן

| קובץ | שימוש |
| --- | --- |
| `index.html` | הגרסה שמוגשת ב-GitHub Pages |
| `מחשבון גיוס.html` | קובץ עצמאי לשליחה או לפתיחה בלחיצה כפולה |

שניהם עצמאיים לחלוטין: הנתונים מוטמעים בתוך ה-HTML, אין קריאות רשת ואין
ספריות חיצוניות. שניהם תוצרי בנייה - **אין לערוך אותם ידנית.**

## שני עקרונות שקובעים את כל השאר

**גזירה קדימה בלבד.** מספר שהוזן בשלב מייצג קבוצה שנמצאת *עכשיו* באותו
שלב. ממנה נגזר רק מה שקורה הלאה. כמה מועמדים היו בשלבים שלפניו הוא מידע
שאין לנו, ולכן הוא לא מוצג.

**כל מספר אומר ממה הוא נגזר.** מתחת לכל מספר בגרף כתוב במפורש
"1,263 מתוך 5,000 ב«בדיקת קבצים»", כדי שלא תהיה אי-הבנה לגבי מקורו.

## מדידה ישירה, לא שרשור אחוזים

לכל זוג שלבים נמדד ישירות מהנתונים איזה חלק מהמועמדים שהיו בשלב הראשון
הגיעו בפועל לשלב השני אחר כך, וכמה ימים זה לקח.

זה חשוב מפני שהמשפך אינו סדרתי: מתוך בדיקת קבצים מגיעים לגיוס 9.9% אבל
ליחב"מ רק 8.9% - כלומר חלק מהמגויסים כלל לא עברו ביחב"מ. שרשור אחוזי מעבר
היה מייצר כאן מספרים שגויים.

## איך נמדד כל שיעור

הנתונים קטועים מימין: מועמד שביצע פעילות סמוך לסוף התקופה עדיין לא הספיק
להתקדם, ובקובץ הוא נראה כמי שנעצר. הראיה ב-`make verify` - יחס הגיוס
בבדיקת קבצים יורד מ-13% בקוהורט מרץ ל-1% בקוהורט יולי, לא מפני שהאיכות
ירדה אלא מפני שלא עבר מספיק זמן.

לכן כל שיעור נמדד בשני בסיסים - אחד על חלון זמן קבוע, ואחד על קוהורטים
שהספיקו להבשיל - **והשיעור שבשימוש הוא הממוצע ביניהם**. המחשבון מציג מספר
יחיד, ושני הבסיסים מוצגים בטבלת הבסיס שבעמוד.

## פקודות

```bash
make          # בניית הנתונים + שני עמודי המחשבון
make test     # 48 בדיקות
make verify   # דוח בדיקה של קובצי המקור
make basis    # טבלת המעברים בשורת פקודה
```

שורת פקודה:

```bash
python3 -m recruit_calc.cli --from file_check 5000
python3 -m recruit_calc.cli --from file_check 5000 --from yachbam 300 --target 400
python3 -m recruit_calc.cli --target 400
```

## עדכון נתונים

מחליפים את קובץ האקסל בתיקיית «נתונים למערכת» ומריצים `make`. אין לערוך
ידנית את `data/recruitment_data.json` או את קובצי ה-HTML.

אם יתקבל קובץ הגשות - מוסיפים אותו ל-`config/params.json` ומריצים `make`.
עד אז שלב «הגשות» מסומן כשלב ללא נתונים ואינו משתתף בחישוב.

## שני מנועי חישוב

יש לוגיקת חישוב גם ב-`recruit_calc/engine.py` וגם ב-JS שבתוך
`web/template.html`. כל שינוי בלוגיקה חייב להיעשות בשניהם.
`tests/test_parity.py` מריץ את שניהם על מאות תרחישים ומוודא שהם מחזירים
בדיוק אותו דבר.

## פרטיות

קובצי המקור מכילים מספרי מועמד. הם נשארים בתיקיית «נתונים למערכת» ואינם
נכנסים לעמוד הבנוי, שמתפרסם באופן ציבורי. המחשבון מכיל נתונים מצרפיים בלבד.

תיעוד מלא: `אפיון המערכת.txt`
